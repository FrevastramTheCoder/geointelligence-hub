# Geospatial Knowledge Catalog

**Audit date:** 2026-10-10  
**Scope:** Current GeoIntelligence Hub source, not a claim that every GIS method is executable.

This catalog separates scientific methods from actual application support. Runtime support is registered in `frontend/src/services/geoaiPlanner.js` and constrained by `IMPLEMENTED_ANALYSES` plus `_run_analysis_impl` in `backend/server.py`. A request may be scientifically meaningful but still not executable here.

## Status vocabulary

- **Implemented:** a named browser or backend path executes the method and returns real output.
- **Partial:** a constrained proxy, single indicator, or limited workflow exists; it is not a general GIS implementation.
- **Knowledge only:** method is documented for explanation and requirements; no execution path is present.
- **Unavailable:** required data, model, dependency, or processing engine is not configured.

## Method records

| Method / aliases | Domain and use | Scientific method / key equation | Inputs and preprocessing | Current implementation | Assumptions, limitations, validation |
|---|---|---|---|---|---|
| CRS and datum handling | GIS foundations; coordinate alignment | A coordinate reference system maps coordinates to an Earth datum and projection. Reprojection applies a defined coordinate operation; it is not a cosmetic relabel. | Source CRS, target CRS, datum operation; preserve axis order and units. | Knowledge only. AOIs use GeoJSON; no general user-layer reprojection service was found in this audit. | Reject or request missing CRS; do not calculate planar distance/area from longitude/latitude as though degrees were metres. |
| Vector geometry operations | Overlay, proximity, measurement | Intersection is shared geometry; buffer is a distance locus; distance depends on a metric CRS or geodesic method. | Valid geometries, consistent CRS, units, tolerances. | Partial: browser buffer, intersection, proximity, area and distance modules. No general clip/union/erase/dissolve/network routing capability was verified. | Geometry validity, multipart behavior, and measurement units must be stated. |
| Raster reprojection, alignment, mosaics | Raster data management | Resampling estimates values on a target grid; nearest neighbour preserves class codes, while bilinear/cubic suit continuous values. | Raster CRS, affine transform, nodata, target resolution and resampling kernel. | Knowledge only for uploaded rasters; Earth Engine manages many collection projections internally. | Never average categorical codes; report scale/CRS and avoid false precision. |
| Optical surface reflectance | Vegetation, water, built-up, LULC | Surface-reflectance composites summarize quality-filtered observations over a specified period. | Sentinel-2 SR Harmonized or Landsat Collection 2 L2; date, AOI, cloud policy and sensor band mapping. | Implemented for Sentinel-2 and Landsat 8/9 paths. Cloud filtering is not equivalent to a complete cloud-shadow QA workflow in every branch. | Match season and sensor; document missing observations, cloud/shadow residuals and scale. |
| SAR and flood extent | Flooded-water observation under clouds | Sentinel-1 VV/VH backscatter change or thresholding can identify open-water-like changes. | Sentinel-1 GRD, orbit/polarization consistency, acquisition dates, terrain effects and reference period. | Partial: Sentinel-1 flood-mapping route exists. | Observed extent is not flood probability, depth, return period or risk. Shadow, urban layover and wet soil can confuse classification. Validate with event observations. |
| Image compositing and temporal series | Cloud reduction, temporal monitoring | Pixelwise median/other reducers summarize valid observations; trend estimates require comparable temporal samples. | Collection, date window, reducer, observation count and quality mask. | Implemented: annual imagery composite and selected time-series/trend analyses. | A median is not a seasonal model. Account for phenology, missing years, sensor transitions and compositing scale. |
| NDVI | Vegetation greenness proxy | `(NIR - Red) / (NIR + Red)`. | Sentinel-2 B8/B4; Landsat 8/9 SR_B5/SR_B4; surface reflectance. | Implemented (`ndvi`, change, trend, drought workflows). | Sensitive to soil background, canopy saturation, atmosphere and phenology; not biomass or crop health ground truth. Thresholds are context-specific. |
| EVI / EVI2 | Vegetation with reduced soil/atmospheric sensitivity | EVI = `2.5*(NIR-Red)/(NIR+6*Red-7.5*Blue+1)`; EVI2 = `2.5*(NIR-Red)/(NIR+2.4*Red+1)`. | Sensor-specific NIR/Red/Blue, unitless surface reflectance. | Both are in the Earth Engine spectral-index engine; scalar formula tests pass. | Coefficients/reflectance scale matter; do not apply EVI equation to unscaled digital numbers. |
| SAVI / MSAVI | Vegetation in exposed-soil settings | SAVI = `((NIR-Red)/(NIR+Red+L))*(1+L)`; current engine uses `L=0.5`. MSAVI uses a nonlinear soil adjustment. | NIR and Red reflectance; document L and band mapping. | SAVI implemented; MSAVI is in spectral-index engine. | L is not universal; indices remain proxies and need local interpretation. |
| NDWI / MNDWI / AWEI | Water detection | NDWI = `(Green-NIR)/(Green+NIR)`; MNDWI substitutes SWIR for NIR; AWEI is a sensor-specific linear combination. | Green, NIR/SWIR bands, sensor mapping, water season and threshold. | NDWI water extent outputs a binary screening layer and area summary at index > 0; MNDWI/AWEI index paths also report thresholded areas. | The fixed threshold is a documented default, not a universal classifier. Calibrate against reference data for sensor, turbidity, built-up surroundings and season. |
| NDMI / NBR / dNBR | Canopy moisture and burn severity | NDMI = `(NIR-SWIR1)/(NIR+SWIR1)`; NBR = `(NIR-SWIR2)/(NIR+SWIR2)`; dNBR is pre-fire NBR minus post-fire NBR. | Sensor-specific NIR/SWIR, comparable pre/post composites, fire timing. | NDMI/NBR compute per-pixel; dNBR computes two annual composites and screening classes/area. Scalar formula tests pass. | dNBR severity classes require calibration and ecological context; use matched seasons and validate with local reference data. |
| NDBI / BSI / IBI / NDSI / other indices | Built-up, bare soil, snow, composite indicators | Ratios/differences of reflectance bands; formulas and bands differ by index/sensor. | Correct sensor bands and unitless surface reflectance; use matched dates. | NDBI, BSI and NDSI are available in `spectral_index`; scalar formulas pass. | Index response is not a universal classifier. Validate thresholds and avoid calling a proxy legal land use or material composition. |
| Land-cover classification | Land-cover mapping | Supervised RF/CART/SVM classify labeled samples; unsupervised K-Means returns arbitrary cluster IDs. | Sensor/year, feature bands/indices, optional labeled WGS84 GeoJSON training and separate validation FeatureCollections; class property and model settings. | EE RF/CART/SVM/K-Means paths, selected bands/indices, optional training samples, independent validation, confusion matrix, OA, producer/user accuracy, F1 and Kappa; area in ha/km². RF has a probability-derived uncertainty proxy where available. Offline sample/metric tests pass. | Without uploaded reference samples, scores are WorldCover-derived spatial holdout only, not independent field accuracy. Cluster labels are not land-cover names. WorldCover training on earlier/later imagery has domain shift. No live EE classification was run in this code audit. |
| Land-cover reference products | Fast reference maps | Use an existing classified product rather than train a new model. | Product's own date, class legend and spatial resolution. | Implemented: Dynamic World, ESA WorldCover, MODIS, Copernicus, GLC_FCS30D, NLCD and CORINE paths (coverage varies by geography/date). | Respect product coverage, scale and legend. A product is not a locally validated map. |
| Change detection | NDVI, water, urban, burn and LULC transitions | NDVI/dNBR differencing; NDWI binary water; NDBI urban mask; Hansen forest-loss period plus static 2000–2012 gain. | Comparable annual composites, same sensor/feature schema, matched class codes; 2–8 LULC dates. | Actual NDVI/water/urban change rasters and class-coded LULC transitions with per-period area tables and annualized area where defined. | Threshold masks need local calibration. LULC training is sourced from 2021 WorldCover and reused temporally, so historical domain shift remains. CA-Markov projections are withheld until a validated map archive and hindcast exist. |
| DEM terrain derivatives | Slope, aspect and relief | Terrain derivatives are computed from elevation; slope/aspect depend on horizontal/vertical units and neighborhood. | SRTM 30 m path, units, scale and AOI; hydrologic conditioning for flow methods. | Implemented: elevation, slope, aspect, hillshade and slope classes. | SRTM is not a survey-grade DTM; slope is resolution-sensitive. No universal DEM conditioning workflow is established. |
| Hydrology and drainage | Flow direction/network and catchments | Flow accumulation aggregates upstream contributing cells; watershed delineation requires a conditioned DEM and outlet. | MERIT Hydro layers and/or DEM, flow algorithm, outlet/catchment definition. | Partial: `hydrology` uses MERIT Hydro; confirm the requested output with actual result metadata. No general user-defined watershed delineation from arbitrary DEM was verified. | A drainage proxy is not calibrated discharge or flood forecast. Check source scale, direction convention and catchment boundary. |
| Flood susceptibility / risk | Planning screening | Current flood route combines terrain indicators; this is a heuristic susceptibility score, not a probability model. | DEM, slope and explicitly defined exposure/vulnerability/hazard layers for risk. | Partial: SRTM terrain proxy labeled flood susceptibility/risk. | Do not report a return period, depth or risk probability. Separate hazard, susceptibility, exposure and consequence. |
| Rainfall, LST, ET, drought, air quality | Climate/environmental indicators | CHIRPS precipitation sum; MODIS LST conversion; MOD16 ET; drought is an NDVI anomaly proxy; S5P/AOD atmospheric products. | Dataset-specific dates, scale factors, units, baseline, QA and coverage. | Implemented for CHIRPS, MODIS LST/ET, NDVI-based drought, S5P NO2/SO2/CO/O3 and MODIS AOD. PM2.5 is explicitly unconfigured. | Current values are Earth Engine dataset outputs, not station-validated local climate, exposure or health estimates. Report units and resolution. |
| Urban indicators | Built-up and urban form | NDBI proxy, Open Buildings footprint count, NDBI temporal metrics/sprawl and thermal indicators. | Sensor/date/season, urban boundary definition, building product confidence and thermal scale. | Implemented as proxies (`ndbi`, `buildings`, `urban_growth`, `sprawl`, UHI/UTFVI). | Do not infer population, legal land use, building completeness, or urban heat exposure from proxies alone. |
| Suitability / MCDA | Screening sites for a stated use | Weighted linear combination: `S(x)=Σ w_i r_i(x)` for normalized criterion scores; weights express stakeholder priorities. | Criteria, normalization, weights, constraints, intended use and sensitivity scenarios. | Partial: server-side suitability has preset defaults and custom numeric weights; slope/water constraints are hard-coded. | Defaults are illustrative, not scientifically established. Ask for weights or explicit acceptance of defaults; report normalization, constraints and sensitivity. Output is relative ranking, not suitability certification. |
| Spatial statistics / geostatistics | Clusters, hotspots, interpolation | Moran's I, local indicators, Gi*, KDE, variograms/kriging each have assumptions about weights, distance, stationarity and sampling. | Georeferenced observations, CRS, spatial weights/bandwidth, study extent and significance design. | Only descriptive summaries and trend/regression + Mann-Kendall time series were verified. Moran's I, Gi*, KDE, spatial regression/GWR and kriging are not implemented. | No inference without a defined null model, multiple-testing policy and spatial validation. Spatially random train/test splits can leak autocorrelation. |
| GeoAI / deep learning | Image classification, detection, segmentation | Deep learning needs labeled examples, model weights, compatible runtime, inference lifecycle and validation. | Imagery, training labels, model, GPU/CPU dependencies, spatial holdout and confidence. | Partial: Earth Engine classical classifiers above. No deep-learning weights, Vertex AI endpoint or segmentation/detection runtime was found. | Do not say a DL model ran unless artifacts and endpoint are configured. Detect domain shift and keep geographically independent validation. |
| Drone photogrammetry / 3D | Orthoimagery, DSM/DTM, point cloud, volume | SfM estimates camera poses and 3D structure; volume is a surface difference relative to an explicit base. | Overlap imagery, camera metadata, GCP/checkpoints, CRS, DSM/point cloud and base surface. | Knowledge only; no SfM, point-cloud or 3D processing runtime found. | Accuracy requires independent checkpoints; do not derive stockpile volume from a lone 2D image. |
| Mining/geology | Prospectivity, disturbance and stockpiles | Weighted prospectivity combines evidence layers; band ratios are alteration indicators, not mineral confirmation. | Geological/lithological/structural layers, validated occurrences, sensor-specific bands, field/lab checks. | Partial: band-ratio mineral indicator, generic suitability, and satellite change proxies. | Never label a proxy as a confirmed deposit or laboratory mineral composition. |
| Cartography/reporting | Map interpretation and reproducible outputs | A map communicates data through an explicit projection, visual variables, legend, scale and source. | Valid outputs, units, CRS, classification breaks, attribution and chosen export format. | Implemented: map tiles/legends/stats and export routes (GeoTIFF/vector/CSV/image options depend on result). Full print layout / north arrow / scale-bar workflow was not verified. | Keep legends and statistics tied to the actual computation; include data date, scale and limitations. |
| Geospatial data engineering | Ingestion and scalable execution | Pipeline stages should preserve CRS, units, lineage, validity and reproducibility; chunking/caching must preserve semantics. | GeoJSON/KML/shapefile/browser layers and Earth Engine assets; metadata and job/result records. | Partial: API-mediated Earth Engine, AOI/layer upload, project/job/result persistence and export. No PostGIS service, general STAC client, COG pipeline or job orchestrator was verified. | Do not claim unconfigured drivers or infrastructure. Preserve data provenance and job parameters. |

## Search and retrieval behavior

`frontend/src/services/methodologyCatalog.js` stores short records with aliases, requirements, limitations, implementation status and relevant tools. `searchMethodologies(query)` ranks a small set of records for each unknown-method request. Retrieval returns only the best match(es); it does not inject the full catalog into every assistant prompt.

A catalog hit never implies execution. The analysis registry remains the execution source of truth, and the backend allow-list remains the final guard.
